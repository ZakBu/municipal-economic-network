# Вклад в проект

1. Создайте или возьмите Issue; назначьте одного ответственного и опишите готовый результат.
2. Обновите локальный main и создайте ветку `feat/<номер>-<описание>`, `fix/...` или `docs/...`.
3. Реализуйте небольшой завершённый результат. Существенное решение зафиксируйте в ADR.
4. Выполните проверки из README. Не добавляйте данные и секреты.
5. Откройте PR, укажите `Closes #<номер>`, проверки и вопросы ревьюеру.
6. Коллега проверяет, автор исправляет замечания, затем PR объединяется squash-merge.

Примеры коммитов: `feat: add source registry`, `docs: describe data access`,
`fix: preserve municipality identifiers`. Научные решения не принимаются шаблоном PR.
Практические команды, конфликты и примеры запросов к Codex — в [TEAM_GUIDE](docs/TEAM_GUIDE.md).
