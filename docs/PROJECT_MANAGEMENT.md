# GitHub Project / Kanban

Рабочая доска: [Project #1](https://github.com/users/ZakBu/projects/1).
Доступ к репозиторию и Project настраивается отдельно. Для управления доской через GitHub CLI
каждый участник выполняет `gh auth refresh -s project` и получает роль в Project от владельца.
Агент сначала проверяет `gh project view 1 --owner ZakBu --format json`; если команда
не проходит, он продолжает локальную работу и точно сообщает, какого доступа не хватает.

## Поля

| Поле | Тип | Значения |
|---|---|---|
| Status | Single select | Backlog, Ready, In progress, Review, Done |
| Priority | Single select | P0, P1, P2 |
| Area | Single select | Coordination, Data, Research, Code, Visualization, Delivery |
| Size | Single select | S, M, L |
| Assignees | Стандартное | Один ответственный; помощники в описании |
| Due date | Date | Реальная дата команды |
| Blocked | Single select | No, Yes |

Views: Board по Status; Table всех задач; My tasks по Assignees; Blocked по полю Blocked.
Автоматизация при наличии: закрытый Issue → Done. Review выставляет автор открытого PR.

## Правила статусов

Backlog — идея работы. Ready — ясны вход и критерии, нет блокеров.
In progress — назначен ответственный и создана ветка. Review — открыт PR и пройдены проверки.
Done — результат принят и PR объединён. Одновременно у участника желательно одна активная задача.
Блокер отмечается отдельно: причина, необходимая помощь, связанная задача.

## Стартовый backlog для переноса в Issues

| Задача | Area | Приоритет | Критерий готовности |
|---|---|---|---|
| Подключить команду и распределить роли | Coordination | P0 | У всех доступ, каждый смог запустить проверки |
| Уточнить требования организаторов | Coordination | P0 | В PROJECT записаны срок и состав сдачи |
| Организовать доступ к исходным данным | Data | P0 | Есть паспорт источников и общий способ получения |
| Согласовать спецификацию первой версии | Research | P0 | Команда приняла краткий spec и критерии |
| Разделить реализацию на задачи | Code | P1 | У каждой задачи ответственный, зависимости и DoD |
| Согласовать формат итоговой демонстрации | Visualization | P1 | Есть согласованный формат и ответственный |

## Настройки репозитория

Уже включены Issues, Discussions, squash-merge и удаление ветки после merge;
wiki отключена, документация хранится в Git.
Владелец приглашает коллег в Settings → Collaborators.
Для main рекомендуется ruleset: PR перед merge, одно ревью коллеги и зелёный CI.
Доступность некоторых ruleset-функций зависит от тарифа и настроек GitHub. Если правило недоступно,
соблюдайте PR-процесс по соглашению команды. Автоматическая защита ветки здесь не заявляется.
